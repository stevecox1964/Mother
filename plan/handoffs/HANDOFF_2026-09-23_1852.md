## TL;DR

Mother chats can now hold Python code cells between messages. Each conversation has one Jupyter kernel. Cells show text, errors and images, and you can collapse them. **Run all** restarts the kernel and runs every cell from top to bottom. - **Storage (`backend/mother/store.py`):** new `cells` table (`id, conversation_id, source, outputs JSON, status, execution_count, collapsed, updated_at, deleted_at`). New methods `add_cell`, `cell`, `cells` (timeline order via the `cell` event's seq), `update_cell`, `decode_cell`. A cell sits in the timeline as an event with `kind="cell"`, `content=""`, `metadata={"cell_id"}`. The events log stays append-only; source and outputs change in `cells`.
- **Kernel runner (`backend/mother/notebook.py`, new):**
  - `Notebook`: one `KernelManager` per conversation, started lazily, cwd = project folder. One lock per conversation, so cells run one at a time.
  - `run()` / `run_all()` start background threads. `run_all` stops the kernel first (clean state), runs in order, and marks the rest `skipped` after the first error or Stop.
  - `execute()` reads iopub messages: `stream` (merged), `execute_result` / `display_data` (PNG/JPEG saved to the project `attachments/` folder, and `text/plain`), `error` (ANSI stripped). Text is capped at 100,000 chars. Old output images are deleted after a re-run.
  - `interrupt()`: sends an interrupt. If the same cell still runs after 5 s, it kills the kernel. **Why:** Windows cannot interrupt `time.sleep`. It checks Stop again right after the kernel starts (this fixed a race).
  - `history_text(cell)`: how a cell reads for models (code, text output capped at 4000 chars, `[Image output]`, error line).
  - `recent_images()`: image outputs from cells after the last user message (max 2), for vision models.
  - Statuses: `new, queued, running, ok, error, skipped, cancelled`.
- **Routes (`backend/mother/app.py`):** `GET /api/conversations/<id>` now also returns `cells`. New: `POST /api/conversations/<id>/cells`, `PUT /api/cells/<id>` (`source`, `collapsed`), `DELETE /api/cells/<id>` (needs a JSON body, like all Mother DELETEs), `POST /api/cells/<id>/run` (optional `source`), `POST /api/conversations/<id>/cells/run-all`, `POST /api/conversations/<id>/cells/stop`. Messages now pass `recent_images` to vision models.

## Decisions locked in this session

- **Cells come from both sources:** the user adds them, or clicks **Make cell** on a model's Python block. Not added by themselves (avoids clutter). A new cell always goes to the end of the conversation.
- **Run all = code only.** Fresh kernel, top to bottom. Chat text stays. No model calls.
- **Only the user runs code.** Models cannot run code.
- **Models see outputs automatically.** Text in history. Up to 2 images from cells since the last user message go to vision models.
- **Kernel = Mother's `.venv` Python.** cwd = the project's `project_path`, or the project folder if that path is missing.
- **Output images reuse the `attachments/` folder and `/api/attachments/<id>`.**
- **No HTML outputs** (pandas tables show as plain text). **Why:** script risk in the page.
