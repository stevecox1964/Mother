## What was done this session

**Picked up from Astra, which ran out of tokens mid-work.** Its last commit-less work (10:22–10:28 that morning) had added `@mentions`, a machine-wide model registry called System setup, and virtual-folder file tools. Two tests were failing.

- Fixed `Store.run()` in `backend/mother/store.py` to return its `members` list, which `tests/test_mentions.py` required.
- Fixed the Mother project's architecture document path. The master plan had moved to `docs/MOTHER_KNOWLEDGE_MODEL_ARCHITECTURE.md`; `backend/mother/projects.py` and the live project config still pointed at the old root path.
- Split `frontend/src/main.jsx` into `frontend/src/components/`. It is now 5 lines and only mounts the app. No logic changed in that step.
- Rebuilt the sidebar as a project tree in `frontend/src/components/Sidebar.jsx`. Every project is a node; the selected one expands to Chat with its conversations nested beneath, then Models, Setup, Search and Trash. System setup sits alone at the bottom.
- Removed the per-model sidebar entries and the `view: "chat"` direct-message screen. Direct mode and `@model` mentions replace them.
- Extracted `Participants.jsx` and `ConversationDialogs.jsx` out of `App.jsx`, taking it from 1,492 to 921 lines.
- Fixed a CSS bug where `.tree-row > button` also matched the row's icon button, so the icon button stretched to 106px and truncated every name.
- **Fixed system model renames.** Each project config held its own copy of the model name and nothing updated it. `SystemConfig.save_system` in `backend/mother/system_config.py` now carries renames into every project config. A project stores `name_alias`; while it is empty the project follows the registry name.
- **Fixed system model deletions.** Deleted connections now drop from every project's model list instead of lingering as disabled ghost rows. The guard that stops a stale browser tab resurrecting one still holds and returns 400.
- **Repaired live data.** `SystemConfig.adopt_registry_names` runs once at startup for configs written before `name_alias` existed. It ran on the real data directory and wrote backups.
- Created the `backlog` skill at `~/.claude/skills/backlog/SKILL.md` and added the first two items.

## Decisions locked in this session

- **The sidebar is a project tree, not a dropdown.** The user chose this explicitly over keeping the dropdown, and chose to nest conversations under Chat rather than give them their own node.
- **The per-model sidebar list is gone.** The user chose to drop it; Direct mode and `@model` mentions cover the same need.
- **A project may rename a model, but only deliberately.** An empty `name_alias` means "follow System setup". This preserves the case where several souls share one connection, which the three Demo profiles already do.
- **Deleting a system connection deletes its project bindings.** The previous behaviour left a disabled ghost row. `tests/test_system_setup.py` was rewritten to assert the new behaviour.
- **Configuration should move to SQLite, but not this session.** The user asked for it as a backlog item. Conversations and search are already in SQLite; only configuration is still JSON.
- **The backlog lives in `plan/backlog/`, never in `CLAUDE.md` or memory.** The user does not want backlog items loading into context every session.
